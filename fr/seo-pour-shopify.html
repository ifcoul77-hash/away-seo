En bref : Shopify gère correctement les bases du SEO technique. Les risques se logent ailleurs : dans les filtres de collection, surtout lorsqu'une application les génère, dans les gabarits du thème, dans le poids des applications installées et dans un balisage produit qui se désynchronise. Ce guide passe en revue cinq points, avec ce que la documentation établit et ce que vous devez encore vérifier sur votre boutique.

Shopify n'est pas un SEO à part, mais il a ses zones sensibles

Une boutique Shopify suit les mêmes règles de classement qu'un site WordPress ou qu'un site sur mesure. Ce qui change, c'est l'endroit où les erreurs se glissent : le système de collections et de filtres, les gabarits du thème et l'écosystème d'applications. Une checklist SEO générique passe souvent à côté de ces trois zones, parce qu'elle ne sait pas où regarder dans Shopify.

Les 5 points à vérifier sur votre boutique

1. Les URL des filtres de collection

Quand un visiteur filtre une collection par couleur, par taille ou par prix, l'adresse de la page change. Une collection dotée de quelques filtres peut ainsi produire, sans bruit, un grand nombre de variantes d'URL pour un contenu presque identique.

Ce que Shopify fait déjà. D'après plusieurs analyses de praticiens (nous n'avons pas trouvé de page officielle Shopify qui le détaille), le robots.txt par défaut bloque déjà les paramètres de tri et les combinaisons de tags, et les pages filtrées avec le filtrage natif pointent leur balise canonical vers la collection propre. À confirmer sur votre boutique, pas à supposer.

Là où ça se complique. Une application de filtrage tierce, un thème modifié ou des liens internes vers des URL filtrées peuvent changer ce comportement.

Documenté par Google. Si vous n'avez pas besoin que les URL de navigation à facettes soient indexées, Google recommande d'en empêcher l'exploration avec le robots.txt. La balise canonical et l'attribut nofollow sont présentés comme d'autres moyens de signaler une préférence (Google Search Central, navigation à facettes).

Notre recommandation. Listez les paramètres d'URL que vos filtres génèrent vraiment, applications comprises. Ouvrez le code source d'une page filtrée et lisez le canonical qu'elle émet. Décidez ensuite filtre par filtre : bloqué, canonicalisé, ou transformé en vraie page de collection quand une demande de recherche réelle le justifie. Shopify permet de personnaliser le robots.txt grâce à un gabarit dédié, robots.txt.liquid.

2. Les descriptions de collection et de produit identiques

Il est tentant de laisser chaque collection avec la même phrase d'introduction, et de reprendre le texte du fabricant sur toutes les variantes d'un produit. Le risque est double : des pages qui se ressemblent trop pour justifier chacune un classement, et des descriptions que dix autres boutiques publient mot pour mot.

Aucune règle chiffrée n'existe ici : nous le présentons donc comme une recommandation, pas comme une exigence documentée. Un texte que vous seul pouvez écrire (usage réel, comparatif, contraintes de taille ou d'entretien) donne à une page une raison d'exister que le texte du fabricant ne lui donne pas.

Notre recommandation. Donnez à chaque collection sa propre introduction. Donnez à chaque produit au moins un paragraphe que le fabricant n'a pas écrit. Commencez par les pages qui rapportent le plus.

3. Les balises title et les meta descriptions

Par défaut, Shopify compose le titre à partir du nom du produit ou de la collection, suivi du nom de la boutique. Cela fonctionne jusqu'au jour où des dizaines de pages se retrouvent avec des titres presque identiques, ou trop longs pour s'afficher en entier. Les champs de personnalisation existent dans l'administration, sur chaque produit, chaque collection et chaque page.

C'est un petit chantier au bénéfice visible : commencez par vos dix pages les plus importantes. Visez environ soixante caractères : l'affichage dépend de la largeur en pixels, et les moteurs peuvent de toute façon réécrire un titre. Les outils pour webmasters de Bing nous ont d'ailleurs signalé des titres trop longs sur une version antérieure de ce guide, ce qui explique que nous insistions.

4. Le poids des applications et les Core Web Vitals

Chaque application installée peut charger son propre JavaScript : widget d'avis, fenêtre de vente incitative, chat, outil de mesure. Selon la façon dont elle est intégrée, ce code peut se charger sur toutes les pages, y compris celles qui n'en ont aucun besoin. Le nombre d'applications compte moins que ce que chacune charge, et à quel moment.

Notre recommandation. Mesurez les Core Web Vitals sur des pages réelles (accueil, collection, produit), en privilégiant les données de terrain quand elles existent. Testez ensuite l'effet du retrait d'une application à la fois, sur une copie du thème. Pensez aussi aux résidus : une application désinstallée peut laisser du code dans le thème.

5. Les données structurées Product

La plupart des thèmes Shopify intègrent un balisage Product de base. Il peut pourtant se casser ou se contredire quand une application modifie le prix, les variantes ou l'affichage des avis, ou quand le thème et une application publient chacun leur propre balisage.

Documenté par Google. Le balisage Product rend une page produit éligible aux résultats enrichis, comme le prix, la disponibilité et les avis (Google Search Central, données structurées Product).

Notre recommandation. Testez vos pages produit avec l'outil de test des résultats enrichis de Google, comparez le prix et la disponibilité balisés avec ceux affichés, et cherchez dans le code source les blocs Product en double.

Checklist d'action concrète

  • Lisez le canonical dans le code source d'une page de collection filtrée,
  • Vérifiez le robots.txt réellement servi par votre boutique,
  • Réécrivez les titres et les meta descriptions de vos dix pages les plus importantes,
  • Donnez à vos principales collections et à vos produits phares un texte qui vous appartient vraiment,
  • Mesurez les Core Web Vitals sur des pages réelles, puis testez le retrait d'une application à la fois sur une copie du thème,
  • Passez vos pages produit dans l'outil de test des résultats enrichis de Google et comparez le prix balisé avec le prix affiché.

Questions fréquentes

Shopify a-t-il des problèmes SEO intrinsèques par rapport à WordPress ?

Pas intrinsèquement. Shopify gère correctement le SEO technique de base (sitemaps, HTTPS, rendu mobile) par défaut. Les problèmes récurrents viennent de la configuration des collections, des filtres et des thèmes, pas de la plateforme elle-même.

Peut-on corriger le SEO Shopify sans développeur ?

Certaines corrections (titres, meta descriptions, texte alternatif, descriptions de collection) se font directement dans l'administration Shopify. D'autres (règles canoniques sur les URL filtrées, données structurées, performance du thème) demandent généralement une modification du code du thème.

Quelles applications Shopify ralentissent le plus souvent une boutique ?

Toute application qui injecte son propre JavaScript sur chaque page, comme les widgets d'avis, les fenêtres de vente incitative ou les trackers, ajoute du poids bloquant le rendu. Ce que chacune charge sur des pages qui n'en ont pas besoin compte plus que leur nombre.
